# AutoContent API

AutoContent API turns a Project's website, reusable Knowledge, or a bounded topic into finished content Assets. The Platform exposes the same Project-centred workflow through an authenticated web app, REST API, TypeScript SDK, CLI, and OAuth MCP service.

## First-class Asset types

The launch catalog contains exactly these public identifiers:

- article
- lead_magnet
- ebook
- slides
- infographic
- quiz
- podcast_episode
- short_video
- explainer_video
- launch_video
- product_demo_video
- ad_video

Use GET /v1/asset-types for the live availability, stable option schemas, capabilities, contract versions, and catalog version. Use GET /v1/models?asset_type=... for pinnable models and their native option schemas. Do not infer provider models or prices.

## Conceptual quickstart

1. Create a Project from one public website URL.
2. Wait for analysis, review the inferred profile, and confirm it.
3. Add reusable URL, text, or file Sources when needed. A multipart file with keep_as_project_asset=false is request-only: it stays outside Collections and expires after 24 hours unless a Generation claims it.
4. Preview a Generation with one or more distinct Asset requests. Pass up to 20 unique ready same-Project Source IDs in top-level attachment_source_ids when they apply only to that request.
5. Accept only under an explicit max_cost_usd equal to or above the current quote.
6. Poll the Generation or consume signed webhooks, then use its Asset Artifacts.
7. Turn useful repeatable work into an explicit Content Loop.

## TypeScript example

```ts
import AutoContent from 'autocontentapi'

const client = new AutoContent({
  apiKey: process.env.AUTOCONTENT_API_KEY,
})

const accepted = await client.projects.create({
  website_url: 'https://example.com',
})
const project = await client.projects.wait(accepted.id)

const draft = {
  project_id: project.id,
  input: { type: 'knowledge' as const },
  attachment_source_ids: ['src_request_brief'],
  assets: [
    { asset_type: 'lead_magnet' as const },
    { asset_type: 'podcast_episode' as const },
  ],
}

const preview = await client.generations.preview(draft)
const generation = await client.generations.create({
  ...draft,
  max_cost_usd: preview.total_cost_usd,
})
const completed = await client.generations.wait(generation.id)
```

## API behavior

- Requests and responses use snake_case.
- Decimal USD values are strings.
- List endpoints return one cursor page; follow next_cursor explicitly.
- OAuth access tokens and Platform API keys use Authorization: Bearer.
- Mutating operations require or support an Idempotency-Key. Retain the same key for the identical logical action and exact body.
- Preview is non-consuming and authoritative. Client code must not calculate or cache customer prices.
- attachment_source_ids is a top-level Generation field, separate from input.source_ids. It accepts up to 20 unique ready Sources owned by the same Project. Request-only uploads are claimed atomically at Generation acceptance. Textual attachments can ground any Asset; Product Visual attachments can guide Lead Magnets and Product Demo Videos only and do not replace textual grounding.
- A payment_required response creates no Generation, reservation, or provider effect.
- Accepted Generations freeze Project, Source, brand, Voice, Avatar, model, option, and catalog identities so later changes do not rewrite in-flight or completed work.
- Existing work may finish during a graceful service deployment.

## Webhook verification

Verify the exact raw body before JSON parsing. The signature is HMAC-SHA256 over `<unix timestamp>.<raw body>`. Require x-autocontent-event-id to equal body.id, reject timestamps outside a plus/minus 300-second window, and deduplicate by event ID. The TypeScript SDK exposes AutoContent.webhooks.constructEvent for this contract.

## Platform MCP boundary

The Platform MCP service is separate from the legacy AutoContent MCP. It validates the exact Platform OAuth issuer, audience, account binding, and scopes, then forwards the bearer to the REST API. Hosted tools accept URL or text Sources and can reference ready same-Project Sources through attachment_source_ids. They do not read arbitrary client-local paths or accept base64 file blobs. Upload files through the Platform, SDK, or CLI first.

## Legacy product

Legacy AutoContent routes, credentials, credit vocabulary, and customer application remain separate. They are not aliases for the Platform /v1 API. New integrations should start at https://autocontentapi.com/developers; migration guidance is at https://autocontentapi.com/developers/legacy.
